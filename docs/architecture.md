# Архітектура прошивки

## Шари

```
┌──────────────────────────────────────────────────────────────┐
│  APP: задачі FreeRTOS, стан-машина доступу, меню, екрани     │  App/
├──────────────────────────────────────────────────────────────┤
│  SERVICES: список карток, журнал, логер, CRC, супервізор,    │  App/
│            RTC, Flash-сховище                                │
├──────────────────────────────────────────────────────────────┤
│  BSP: rc522, gc9a01, gfx, joystick, lock, buzzer             │  Drivers/BSP/
├──────────────────────────────────────────────────────────────┤
│  HAL + CMSIS + FreeRTOS + USB Device (CubeMX)                │  Core/, Drivers/, Middlewares/, USB_DEVICE/
└──────────────────────────────────────────────────────────────┘
```

Кожен шар викликає лише шар під собою. Драйвер RC522 не знає про картки власника, стан-машина не знає про регістри SPI. Модулі без HAL (`access_ctrl`, `access_list`, `event_log`, `menu`, `crc32`, `timeutil`, `joystick_math`) збираються й тестуються на ПК.

## Задачі

| Задача | Пріоритет | Стек, слів | Власник периферії | Що робить |
|---|---|---|---|---|
| `tSuper` | Realtime | 384 | IWDG, LED, RTC init | «Пульс» усіх задач, годує watchdog, статистика |
| `tCtrl` | High | 640 | замок, TIM3 (зумер), Flash, RTC | Стан-машина, команди меню, журнал |
| `tRfid` | AboveNormal | 384 | SPI1, RC522 | Опитування 10 Гц, перевірка чипа 1 Гц |
| `tInput` | Normal | 384 | ADC1, кнопки | Джойстик 50 Гц, EXTI-кнопки з антидребезгом |
| `tUi` | BelowNormal | 768 | SPI2 + DMA, GC9A01 | Малює екрани за командами `tCtrl` |
| `tNet` | Low | 256 | USART1 + DMA, ESP | Заглушка до M5: тримає ESP у reset |
| `tLog` | Low | 512 | USB CDC | Лог + консоль |

Стеки трохи більші за початковий план, бо логер форматує рядки через `vsnprintf` у контексті задачі. Реальний запас видно командою `stat` (`uxTaskGetStackHighWaterMark`); за результатами вимірювань на платі стеки можна підрізати. `configCHECK_FOR_STACK_OVERFLOW = 2`: переповнення → запис причини → reset.

`defaultTask`, яку створює CubeMX, лише ініціалізує USB (`MX_USB_DEVICE_Init`) і завершується (`osThreadExit`).

## Потоки даних

```
 tRfid ──EV_CARD/EV_RFID_*──┐
 tInput ─EV_JOY_*/EV_EXIT───┤                      ┌──> qUi ────> tUi ──> дисплей
 osTimer ─EV_TIMEOUT────────┼──> qCtrl ──> tCtrl ──┼──> qNetTx ─> tNet ─> ESP (M5)
 tLog ───EV_CONSOLE─────────┘   (стан-машина)      └──> замок, зумер, Flash (напряму)

 будь-яка задача ──LOG_INFO()──> qLog ──> tLog ──> USB CDC
 кожна задача ──SUP_Heartbeat() (час "я жива")──> tSuper ──> IWDG
```

- **Події** (`AppEvent`, `app_events.h`) — єдина мова між задачами.
- **Команди екрану** (`UiCommand`, `ui.h`) містять усі дані для малювання: `tUi` ніколи не читає список карток чи журнал. Застарілі команди в черзі відкидаються — важливий лише останній стан.
- **Лог** не блокує: повна черга → рядок відкидається і рахується (`stat`).

## Стан-машина як чиста функція

```c
void AC_HandleEvent(AccessCtx *c, const AppEvent *ev, uint32_t now);
```

Стан-машина робить усе через шість функцій з `access_io.h`: `IO_Lock`, `IO_Sound`, `IO_Timer`, `IO_Screen`, `IO_Log`, `IO_SaveCards`. На платі їх реалізує `tCtrl` (справжній замок, зумер, таймер FreeRTOS, дисплей, Flash), у тесті — підробка, яка лише запам'ятовує виклики. Стан змінюється лише в одній функції `go_to()`, яка заодно ставить замок, таймер і екран відповідно до нового стану. Час приходить параметром, тому таймаути тестуються без реального часу.

Зміни списку карток роблять прямо в стан-машині за однією схемою: копія списку в `undo` → зміна в RAM → `IO_SaveCards()`. Якщо запис у Flash не вдався — список повертається з копії, користувач бачить «Помилка Flash».

Застарілі таймаути (подія таймера, яка вже стояла в черзі, коли стан змінився) відкидаються за дедлайном — це окремо покрито тестом.

## Надійність

| Механізм | Реалізація |
|---|---|
| Watchdog | IWDG ~4 с (LSI 32 кГц / 128 × 1000). Годує лише `tSuper` і лише якщо всі 6 задач надіслали heartbeat за останні 2 с |
| Причина reset | `RCC->CSR` + backup-регістр RTC `BKP0R = 0x5AFE | причина | задача`. Після перезавантаження: `reset cause: watchdog (task tCtrl: hung)` і подія `WATCHDOG_RESET` у журналі |
| Переповнення стеку, нестача heap, HardFault | хуки FreeRTOS / обробник → запис причини → reset; під налагоджувачем — зупинка на `BKPT` для Fault Analyzer |
| Налагодження | під підключеним налагоджувачем IWDG заморожується (`DBGMCU`), щоб breakpoint не перезавантажував плату |
| Flash | CRC32 над заголовком і записами, порядок «стерти → записи → заголовок останнім», читання-перевірка після запису, перевірка під час старту, що прошивка не заходить у сектор даних |
| Зчитувач | `VersionReg` + конфігурація антени перевіряються щосекунди; 2 невдалі перевірки → `EV_RFID_FAULT`, спроба ре-ініціалізації раз на секунду |
| Живлення зчитувача/дисплея | помилка ініціалізації дисплея не зупиняє систему: замок працює «наосліп» |

### Чому стирання Flash не вбиває watchdog

Стирання 128-КБ сектора на F411 триває типово 1 с, максимум 2 с (RM0383), і весь цей час CPU стоїть — код виконується з тієї ж Flash. Тому таймаут IWDG збільшено до ~4 с, а перед стиранням `storage.c` один раз годує watchdog (`SUP_KickWatchdog`). Тік FreeRTOS під час зупинки CPU теж стоїть, тож супервізор не бачить «пропущених» heartbeat-ів.

## Пам'ять

- Без `malloc` після старту: усі об'єкти RTOS створюються в `App_CreateRtosObjects()` до запуску планувальника, решта — статичні буфери.
- DMA-буфер дисплея — статичний (10 рядків, 4,8 КБ), повний кадр не зберігається: 240×240×2 = 115 КБ не влізли б у 128 КБ RAM.
- Таблиці (ініціалізація дисплея, шрифт, мелодії, меню) — `const`, лежать у Flash.
- Остання 128-КБ секція Flash (сектор 7, `0x08060000`) виключена з лінкер-скрипту і належить списку карток.

## Відхилення від початкового плану (і чому)

| План | Зроблено | Причина |
|---|---|---|
| RTC у CubeMX (LSE) | RTC налаштовується в `app_time.c` регістрами | Згенерований код зависає в `Error_Handler` назавжди, якщо кварц 32 кГц не стартує; тут — таймаут і перехід на LSI |
| IWDG ~2 с | ~4 с | Стирання сектора Flash до 2 с |
| USART1 RX DMA Normal | Circular | Прийом без пауз між пакетами для `ReceiveToIdle` (M5) |
| Шрифт `font_16.c` | `font5x7.c` з масштабуванням ×1…×4 | Власний шрифт із українськими літерами, генерується `Tools/fontgen.py` |
| `app_freertos.c` | `freertos.c` | Так називає файл CubeMX для серії F4 |
