# Тест-план

Два рівні: автоматичні тести логіки на ПК (кожна зміна) і ручні сценарії на платі (кожен етап). Лог і консоль — через USB-C у будь-якому терміналі (PuTTY, Tera Term, `screen`).

## 1. Автоматичні тести на ПК

```bash
cd firmware-stm32/SmartDoorLock/Tests && make
```

| Набір | Що покриває |
|---|---|
| `test_access_ctrl` | усі переходи стан-машини, блокування після 5 спроб, вікно 60 с, скидання лічильника, відновлення адміна і перше налаштування через код, несправність зчитувача, меню, додавання/видалення/налаштування, помилки сховища, захист первинного налаштування, застарілі таймаути, відлік блокування |
| `test_access_list` | еталон CRC32, додавання/пошук/класифікація, повний список, правило «останній адмін», запис-читання, пошкоджений запис / заголовок / налаштування, **збій живлення на кожному 3-му байті запису**, помилка стирання, межі часу відкриття |
| `test_joystick_math` | нормалізація з несиметричним центром, мертва зона, захист від поганого калібрування, напрямки, гістерезис |
| `test_event_log` | порядок «новіші першими», переповнення кільця, обрізання UID |
| `test_timeutil` | епохи, високосні роки, дні тижня, розбір і формат дати, некоректний ввід |

## 2. Сценарії на платі

Позначення: **Л** — що має з'явитися в лозі, **Е** — на екрані, **З** — звук.

### M0 — скелет

| # | Дія | Очікування |
|---|---|---|
| 0.1 | Увімкнути, відкрити COM-порт | **Л** `SmartDoorLock 0.4.0, reset cause: power-on`, `RTC on LSE`, `LCD full frame: DMA … us`; LED блимає 1 Гц |
| 0.2 | `stat` | heap, запас стеку всіх 7 задач, жодна не > 80 % |
| 0.3 | `hang tInput` | **Л** `task tInput silent … reset follows`; LED світиться постійно; через ~4 с плата перезавантажується; **Л** `reset cause: watchdog (task tInput: hung)`; `log` містить `WATCHDOG_RESET` |
| 0.4 | Повторити 0.3 для `tCtrl`, `tUi`, `tLog` | те саме (для `tLog` рядки після reset) |
| 0.5 | Поставити breakpoint, постояти > 10 с | плата **не** перезавантажується (IWDG заморожений під налагоджувачем) |
| 0.6 | `reboot` | **Л** `reset cause: software (console reboot)` |

### M1 — драйвери

| # | Дія | Очікування |
|---|---|---|
| 1.1 | Старт | **Л** `RC522 ready, version 0x92` (або 0x91/0x88/0xB2 у клонів), `joystick center x≈2048 y≈2048` |
| 1.2 | Покрутити джойстик у меню | курсор рухається в правильний бік (інакше — `CFG_JOY_INVERT_*` / `CFG_JOY_SWAP_XY`) |
| 1.3 | Утримати ↓ у списку | автоповтор через 0,5 с, далі ~5 разів/с |
| 1.4 | Від'єднати RC522 | за ≤ 2 с **Е** «ЗБІЙ Зчитувач RFID», **З** помилка, **Л** `RC522 not responding` |
| 1.5 | Під'єднати назад | **Л** `RC522 recovered`, **Е** «ЗАЧИНЕНО» |
| 1.6 | Логічним аналізатором на PB10/PB15 | SCK 24 МГц; під час заливки екрана — суцільні DMA-блоки по 4800 байт з короткими паузами між ними |
| 1.7 | Осцилографом/аналізатором на PB4 | OK = 2500 Гц, «відмова» = 600 Гц, сирена чергує 3500/2200 Гц |

### M2 — основний цикл

| # | Дія | Очікування |
|---|---|---|
| 2.1 | Своя картка | **Е** зелене «ВІДЧИНЕНО», **З** два високі, PB13 = 1 на 5 с, потім «ЗАЧИНЕНО» |
| 2.2 | Своя картка двічі поспіль за 1 с | зчитується один раз (HLTA + фільтр 2 с) |
| 2.3 | Своя картка, через 3 с ще раз | час відкриття рахується від другого прикладання |
| 2.4 | Чужа картка | **Е** червоне «ВІДМОВА» на 1,5 с, **З** довгий низький, замок не спрацьовує |
| 2.5 | Дві картки одночасно | нічого не відбувається (колізія ігнорується) |

### M3 — збереження і меню

| # | Дія | Очікування |
|---|---|---|
| 3.1 | Перший старт з порожньою Flash | **Е** «НАЛАШТУВАННЯ / Утримайте кнопку джойстика 3 с»; картка ігнорується з «відмовою» |
| 3.2 | Утримати кнопку джойстика 3 с → картка → ↑ ↑ ↓ ↓ ← → ← → | «Адміна додано», далі «ЗАЧИНЕНО» |
| 3.3 | Адмін-картка → «Додати картку» → нова картка | «Картку додано»; `cards` показує `Card 01` |
| 3.4 | Вимкнути живлення, увімкнути | нова картка відчиняє; `cards` без змін |
| 3.5 | «Видалити картку» → вибрати адміна (єдиного) | «Останній адмін», нічого не видалено |
| 3.5a | Заміна адміна: «Додати адміна» → нова картка → «Видалити картку» → старий адмін | «Адміна додано», потім «Картку видалено»; меню відкривається лише новою карткою |
| 3.6 | «Час відкриття» → 10 с → клік | своя картка далі відчиняє на 10 с, після перезавантаження теж |
| 3.7 | Меню, нічого не робити 30 с | повернення в «ЗАЧИНЕНО» |
| 3.8 | Під час збереження (≈1–2 с) | плата не перезавантажується watchdog-ом |
| 3.9 | Пошкодити сектор (ST-Link: записати 0 у `0x08060010`) і перезавантажити | **Л** `card list failed its CRC check`, у журналі `STORAGE_CORRUPT`, режим налаштування |

### M4 — безпека

| # | Дія | Очікування |
|---|---|---|
| 4.1 | 5 чужих карток за хвилину | на 5-й **Е** «БЛОКУВАННЯ, Зачекайте 60 с» з відліком, сирена ~3 с |
| 4.2 | Своя картка під час блокування | не відчиняє, подія `ACCESS_DENIED` у журналі |
| 4.4 | Через 60 с | «ЗАЧИНЕНО», своя картка знову працює |
| 4.5 | 4 чужі, пауза > 60 с, ще 1 | лише «ВІДМОВА», без блокування |
| 4.6 | `time 2026-09-26 12:00:00`, прикласти картку, `log` | запис з цим часом; у меню «Журнал» те саме |
| 4.7 | Натиснути reset (не вимикаючи живлення) | час продовжує йти (`time`) |
| 4.9 | Утримати кнопку джойстика 3 с → нова картка → ↑ ↑ ↓ ↓ ← → ← → | «Адміна замінено»; нова картка відкриває меню, стара — «ВІДМОВА»; звичайні картки працюють; у журналі `ADMIN_RECOVERY` |
| 4.10 | Те саме, але помилитися на 1-му кроці | до 8-го кроку жодної реакції, потім «Невірний код»; адмін не змінився |
| 4.11 | 5 разів невірний код за хвилину | «БЛОКУВАННЯ» |
| 4.12 | Утримати кнопку джойстика в меню або під час блокування | нічого не відбувається |
