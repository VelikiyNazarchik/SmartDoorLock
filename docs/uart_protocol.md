# Протокол STM32 ↔ ESP (етап M5)

> Специфікація для M5. Зараз `tNet` тримає ESP у reset, але `tCtrl` уже формує рядки `EVT:` / `STATE:` і кладе їх у `qNetTx` — у лозі на рівні DEBUG видно, що піде в мережу.

Фізичний рівень: USART1, 115200 8N1, 3,3 В. STM32 приймає через DMA в кільцевий буфер з `HAL_UARTEx_ReceiveToIdle_DMA`.

Кадр: ASCII-рядок, закінчується `\n`, не довше 64 символів разом із `\n`. Поля розділені `:`. Невідомі або задовгі рядки відкидаються з `ACK:<seq>:ERR:<код>`, якщо в них був `seq`.

## Від ESP до STM32

| Рядок | Значення |
|---|---|
| `PING` | перевірка зв'язку |
| `CMD:UNLOCK:<seq>:<token>` | відчинити з телефона |
| `CMD:STATUS:<seq>` | запит стану |
| `TIME:<unix>` | час з NTP для RTC |

## Від STM32 до ESP

| Рядок | Значення |
|---|---|
| `PONG` | відповідь на `PING` |
| `ACK:<seq>:OK` / `ACK:<seq>:ERR:<код>` | результат команди |
| `STATE:LOCKED` / `UNLOCKED` / `DENIED` / `LOCKOUT` / `FAULT` / `SETUP` / … | стан після кожної зміни |
| `EVT:ACCESS_OK:<uid>` | вхід за карткою (hex UID) |
| `EVT:ACCESS_DENIED:<uid>` | відмова |
| `EVT:LOCKOUT` | блокування після перебору |

## Правила безпеки

- `seq` — 32-бітний лічильник команд. STM32 пам'ятає останній прийнятий `seq` і відкидає ≤ нього (`ERR:REPLAY`) — повтор перехопленої команди не спрацює.
- `token` на першому кроці — спільний секрет (`ERR:AUTH` при невідповідності). Наступний крок — `HMAC-SHA256(key, "UNLOCK:" + seq)`, тоді секрет не передається лінією.
- `CMD:UNLOCK` ігнорується, поки біля пристрою відкрите адмін-меню (так уже працює стан-машина).
- Команди з мережі потрапляють у ту саму стан-машину, що й картки, тому всі правила (журнал, звук, таймер закриття) однакові.

## Коди помилок

| Код | Причина |
|---|---|
| `FORMAT` | не той формат рядка |
| `AUTH` | неправильний token / HMAC |
| `REPLAY` | `seq` не більший за попередній |
| `BUSY` | адмін-меню відкрите |
